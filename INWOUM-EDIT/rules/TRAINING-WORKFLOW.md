อ่าน EDITING_RULES.md ใช้ TEAM_GUIDE/templates/JOB-BRIEF.md และ TEAM_GUIDE/QA-CHECKLIST.md

## 0. ตั้งงานและตรวจความสามารถ

ระบุผู้ตัด ผู้ตรวจ กติกาเวอร์ชัน XML ล่าสุด Premiere 2024 และ Sequence 50fps ตรวจว่าอ่านภาพ/เสียงได้อย่างไร ฟังเสียงตรงได้จริงหรือเพียง ASR/VAD ห้ามสัญญาว่าฟังครบถ้าทำไม่ได้ พนักงานเป็นผู้ฟังใน Premiere ได้โดยบันทึกชื่อและ revision

## 1. ตรวจไฟล์และต้นฉบับ

ตรวจสื่อทุกตัวที่ XML อ้างอิง ชื่ออย่างเดียวไม่ยืนยันสื่อเดียวกัน บันทึก SHA256 XML, path/ขนาด/mtime/duration สื่อ และ hash เต็มเมื่อจำเป็นก่อนใช้ cache เก่า

เก็บต้นฉบับ/Sequence เดิม ไม่ใช้ร่างเก่าหรือ XML ผู้ใช้ผิด revision หากไฟล์เพิ่ม/XML เปลี่ยน ทำ mapping ใหม่ ตรวจ sync หัว/กลาง/ท้ายก่อนตัด

ตรวจ source time กับ sequence time, tracks/ช่องเสียง, gaps/offsets, rate/rotation/gain/effects เดิม ตัวสร้างรองรับขอบเขตจำกัด: หนึ่ง Sequence integer50fps ไม่มี speed change/transition ที่ window() ไม่รองรับ ถ้าไม่รองรับให้เก็บต้นฉบับและระบุเหตุ ไม่ flatten/เปลี่ยน timing เงียบ ๆ

## 2. วิเคราะห์ทั้งเรื่อง

ครอบคลุมทั้งความยาวและทุกไฟล์ ไม่ใช้ตัวอย่าง60วินาทีแทนงานเต็ม บันทึกช่วงที่อ่าน/ดูไม่ได้

ทำตารางสินค้า/รุ่น → ประเด็น → วิธี/เงื่อนไข → การใช้ → ผล/ข้อจำกัด → source range → ผู้พูด/ความชัด แยกคุยทีม เทคใหม่ คำเสี่ยง และ Hook inventory (ตั้งใจถ่าย/อนุมาน)

ชื่อ รุ่น หน่วย ราคา ตัวเลขจาก ASR ต้องตรวจเพิ่ม อย่าใช้คำใบ้สินค้าโปรเจกต์เก่า ถอดเสียงเริ่ม0และครอบคลุมงาน เช่น:

```powershell
.\.venv\Scripts\python.exe -X utf8 transcribe_sample.py '<source.mp4>' --prefix '<job>/transcript' --start 0 --seconds <duration> --model '<model-folder>' --device cpu --no-prompt
```

CUDA ใช้เมื่อเครื่องตั้งค่าและทดสอบแล้ว WAV16k mono ช่วยค้นเนื้อหา ไม่ใช่ master เสียง Premiere การ reuse WAV ต้องยืนยันที่มา ไม่ใช่แค่เวลาเท่ากัน

## 3. วางเวอร์ชัน

คำตอบผู้ใช้ล่าสุด:พิจารณาทั้งเทคชัดกระชับและเทคอารมณ์ขายดีเป็นคนละตัวเลือก ทำทุกHookที่ใช้ได้แม้แกนกลาง/ท้ายเหมือนกัน หากท่อนพูดไม่ครบให้ลองเรียงกับท่อนอื่นให้เข้าใจจบความก่อน ถ้ายังค้างให้ทิ้ง ไม่ฝืนเก็บคนหลังกล้องหรือเสียงไม่ชัดที่ไม่จำเป็น รักษาบริบทเมื่อเอาคำถามออก
ก่อนปิดชุดคัทให้ทำ“รอบเก็บตกฟุตเทจที่ยังไม่ใช้”จากแผนที่usage:ตรวจช่วงไม่ใช้ยาวทุกช่วงเป็นรายประโยค บันทึกHook/สาระใหม่/เทคทางเลือก/ภาพใช้งาน/คำสรุป/เหตุไม่เลือก แยกยังไม่มีเวอร์ชันรองรับออกจากคุยทีม/รอ/คำต้องห้ามจริง ถ้ามีมุมมีสาระพอให้สร้างเวอร์ชันเพิ่มหรือปรับเวอร์ชันเดิม อย่าหยุดเพราะครบจำนวนคลิปที่ตั้งไว้ ดูตัวอย่างตกหล่นใน output/Test07/FOOTAGE-UTILIZATION-LEARNING.md การนับsourceที่ใช้ไม่ซ้ำกับความยาวรวมทุกเวอร์ชันต้องแยกกัน และไม่มีโควตาใช้ฟุตเทจ100%
ใช้คำชี้แจงล่าสุดใน TEAM_GUIDE/STYLE-UPDATES.md: ทำHookหลายแนวรวมpain point/ความกลัวและโทนขายที่ผู้ใช้อนุญาต ไม่ทิ้งHookดีเพียงเพราะคำพูดเวอร์หรือพูดถึงยุโรป ให้เนื้อหาตามมาตอบประเด็น Hookราคาเชิงคุณค่าใช้ได้เมื่อไม่ระบุเงิน ตัวอย่างช็อตดึงสายกับคำแข็งแรง/มีลวดเป็นรายละเอียดที่ควรพิจารณาเก็บ ไม่ทำเกณฑ์เหล่านี้เป็นการกรองkeywordอัตโนมัติ
อ้างอิงข้อสังเกตทีม EX07 ที่ output/EX07/LEARNINGS.md:พิจารณามุมกลุ่มผู้ชม สถานการณ์ ปัญหา และกลไกเฉพาะด้วย ไม่จำกัดว่ามีแต่FULL/ไฮไลต์/ทดสอบ และไม่บังคับจำนวนแบบตามตัวอย่าง รักษาเหตุใช้→กลไก→วิธีใช้/ข้อจำกัดที่ทำให้เข้าใจ ไม่ตัดบริบทจนเหลือรายการคุณสมบัติเพียงเพื่อให้สั้น กติกาผู้ใช้เรื่องเงิน/คำเสี่ยงยังเหนือกว่าตัวอย่าง
เต็มไม่เกิน180วินาทีรวม Hook และคลิปประเด็น/จุดเด่น/ทดสอบ/วิธีใช้ตามสาระ ใช้ prepared Hook เมื่อมี ฟุตเทจซ้ำข้ามเวอร์ชันได้ ระบุแต่ละคลิปตอบอะไร ต้องมีบริบท วิธี ผลและข้อจำกัดอะไร ไม่บีบเวลาจนเรื่องขาด

## 4. เลือกท่อน แล้วเกลาภายในทุกท่อน

เลือกวลี/การกระทำครบก่อน แล้วตรวจคำซ้ำ ใจความซ้ำ คำแทรก dead air เสียงหลังกล้อง หัวท้ายคำทีละท่อน การเก็บทั้งวลีไม่ยกเว้นการเกลา ความสั้น/คัทถี่ไม่ยืนยันคุณภาพ

ช่วง test ต้องระบุสิ่งที่เห็นเปลี่ยน ตัดหยิบ/รอที่ไม่เพิ่มข้อมูล เก็บเสียงใช้งานต้นฉบับเป็นค่าเริ่มต้น ห้าม mute ทั้งช็อตเพื่อเอาคำแทรกออก ถ้ายังฟังยืนยันไม่ได้ให้คงเสียงและทำเครื่องหมายรอตรวจ ใช้ XML ผู้ใช้แก้ source เดียวกันเป็นฐาน ไม่ตัดตาม ASR/VAD อัตโนมัติ

## 5. ประกอบและตรวจทุกรอยต่อ

- ห้ามmute/Disableเสียงหรือทำเสียงเงียบแทนท่อนใด ผู้ใช้ไม่รับช็อตปิดเสียง เลือกตัดท่อนนั้นออกทั้งภาพเสียงหรือเก็บพร้อมเสียงต้นฉบับ ตรวจenabledของclip/trackทุกช่องและการลดgainจนเงียบ ไม่ใช้การmuteแก้เสียงหลังกล้อง
- ตรวจเฟรมแรกและการเริ่มเสียงของทุกเวอร์ชัน: เข้าคำพูดหรือแอคชั่นที่มีสาระทันที ไม่มี dead air นำหน้า ไม่เฉือนพยัญชนะต้นเพื่อให้ผ่านเช็กนี้
- ตรวจภายในแต่ละ test ด้วย แยกช่วงที่จำเป็นต้องเห็นผลออกจากช่วงรอ/มือค้าง/ไม่เพิ่มข้อมูล และ jump cut ช่วงหลังได้ ไม่บังคับเก็บเทคเดียวต่อเนื่องทั้งหมด ตัวอย่างขอบคัทผู้ใช้ TEST06 อยู่ output/Test06/USER-LEARNING.md
ใช้ mapping ที่ตรวจแล้ว รักษาภาพเสียง/pproTicks สร้าง revision ใหม่ ตรวจสองฝั่งว่าคำไม่ขาด ไม่มีเศษหัว/คำย้ำใหม่ คำอ้างถึงมีบริบท ปฏิเสธ/เงื่อนไขยังอยู่ และ pause ไม่บวกยาว ดูภาพด้วย ASR อ่านถูกไม่แทนเสียงผ่าน

## 6. ดู/ฟังทั้งเวอร์ชัน

ผู้ฟังได้ตรวจทุกเวอร์ชันจากต้นจนจบหลังคัทล่าสุด ดูความหมาย จังหวะ ซ้ำ ความเสี่ยง สินค้า/รุ่น และเวลา ไม่ใช้การฟังแยกท่อนแทน ลงหลักฐานตามจริง

ถ้าผู้ช่วยฟังไม่ได้ audio_edges/audio_continuity/full_playthrough ยังค้าง ให้ผู้ตรวจที่ฟังจริงลงผลใน Premiere ไม่เพิ่มช่องเช็กแล้วกรอกผ่านแทนการทำงาน

## 7. ตรวจเครื่องมือและนำเข้า Premiere

```powershell
.\.venv\Scripts\python.exe -X utf8 build_project_drafts.py '<plan.json>'
.\.venv\Scripts\python.exe -X utf8 check_project_drafts.py '<output-folder>' --structure-only
.\.venv\Scripts\python.exe -X utf8 delivery_gate.py '<output-folder>' --check
```

ตัวสร้างทำ editorial-review.json เป็น pending และ RELEASE-STATUS.json=not_ready ต้องมีหลักฐานจริงก่อนผ่าน gate เปลี่ยน manifest/XML/WAV ผลเดิมใช้ไม่ได้ อย่าเปลี่ยน hash หลบการตรวจ

check_project_drafts.py ตรวจโครงสร้างตามต้นแบบที่รองรับ ไม่รับรองสื่อเครื่องปลายทาง rendering stereo/gain/effects ลิปซิงก์จริง หรือ Premiere import ตัว gate ตรวจหลักฐานที่กรอก ไม่ฟังหรือจับโกหกแทนคน

นำเข้าเป็น Sequence ใหม่ใน Premiere2024 ตรวจ offline, rotation/scale, syncหัว/กลาง/ท้าย, ช่องเสียง/mute, duration, ภาพกระโดด และ export range บันทึก HANDOFF.md การผ่าน gate ไม่แทนขั้นนี้

## 8. ส่งด้วยสถานะตรงจริง

- กำลังตัด: ยังเลือก/เกลาอยู่
- คัทให้เปิดตรวจ: มี XML และผลบางส่วน ส่งได้เมื่อผู้ใช้ขอไฟล์/สั่งทำต่อหลังทราบข้อจำกัด ระบุค้าง ไม่เรียกว่าผ่านครบ
- เนื้อหา/เสียงและโครงสร้างตรวจแล้ว: gate ผ่านตามหลักฐาน ผลนำเข้าแยกต่างหาก
- พร้อมใช้ใน Premiere หลังตรวจ: ดู/ฟัง revision นี้จริงและบันทึกผลนำเข้าครบ
- ผู้ใช้อนุมัติ/ส่งออกแล้ว: ลงเมื่อผู้ใช้หรือผู้รับผิดชอบยืนยัน ไม่อนุมานจากสร้าง XML สำเร็จ

ส่ง XML รวม/รายแบบ พร้อมชื่อ ประเด็น เวลา source path และข้อค้าง ตรวจ path บนเครื่องทีม ไม่ส่ง .venv/cache/credentials ทั้งเครื่อง

## 9. รับการแก้และบันทึก

เทียบ XML ผู้ใช้กับ revision ที่ส่งจริง: ลบ ย้าย คืนคำ เกลา pause/crossfade แยกกติกากลางจากเรื่องเฉพาะงานและการอนุมาน เก็บตัวอย่างก่อน/หลังพร้อมเหตุผล

เจ้าของสไตล์อนุมัติกติกากลางเวอร์ชันใหม่ก่อนแจกทีม ร่าง AI ที่ยังไม่ยอมรับไม่ใช่ gold reference ดู TEAM_GUIDE/LEARNING-EXAMPLES.md
